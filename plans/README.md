# Animation improvement plans

Generated by `/improve-animations` against commit `fe27d3a`. Source audit
covered the whole app (single-file `styles/main.css`, no motion library,
no build step). Full findings table (including items not turned into
plans — #4 shimmer easing, #5 token consolidation, #6 player-overlay
easing, #7 progress-bar width, #8 debug-panel `right`) lives in the chat
history that produced these plans, not duplicated here.

## Plans

| # | Title | Severity | File(s) touched | Status |
| --- | --- | --- | --- | --- |
| [001](001-bookmark-picker-entrance-animation.md) | Animate the entrance of every `.bookmark-picker` dialog | MEDIUM | `styles/main.css` | DONE |
| [002](002-exit-dialog-scale-transition.md) | Smooth the exit-dialog button scale so it doesn't snap | MEDIUM | `styles/main.css` | DONE |
| [003](003-login-label-transform-transition.md) | Replace the login floating label's `transition: all` with a transform-only animation | MEDIUM | `styles/main.css` | DONE |

## Recommended execution order

**002 → 003 → 001**, smallest/safest first:

1. **002** is a single line added to one existing rule (`.exit-btn`) — no
   new rules, no new keyframes, essentially zero risk.
2. **003** touches two existing rules in one component (`.login-field-label`
   and its combined-selector modifier), removing two lines and adding two —
   still fully contained, no new rules.
3. **001** is the largest of the three: two new `@keyframes` blocks and two
   modified rules, and it's the one most worth a real on-device feel-check
   since it changes the *arrival* motion of nearly every dialog in the app.

## Dependencies between plans

None. All three touch only `styles/main.css`, but in three disjoint
sections (`.exit-btn` around line 90, `.login-field-label` around line 210,
`.bookmark-picker`/`.bookmark-picker-sheet` around line 4049) — they can be
executed in any order, including in parallel by different agents, without
conflicting.

**One caveat if executing sequentially in the same working copy**: every
plan cites exact line numbers from the commit-`fe27d3a` version of the
file. Once an earlier plan in the sequence has added/removed lines, every
line number below that point in the file shifts. Each plan's Steps section
is written to be located by selector text (e.g. "search for
`.login-field-label {`"), not by line number alone — an executor hitting a
line-number mismatch on a later plan should re-locate by selector text
before concluding the code has drifted for real.

## Not turned into plans (from the full audit)

- **#4** `.shimmer` missing `linear` on its infinite sweep — trivial, but
  not requested this round.
- **#5** No CSS custom-property tokens for the `0.15s ease-out` focus-ring
  convention; ~40 rules hand-retype the same value already inherited from
  the `[data-focusable]` base rule — a consolidation/cleanup item, not a
  feel issue.
- **#6** `.player-overlay`'s opacity fade uses default `ease` instead of a
  stronger `ease-out` — minor cohesion nit.
- **#7** `.player-progress-bar` animates `width` instead of
  `transform: scaleX()` — flagged but recommended to skip; low realistic
  cost at this element's update frequency, and the fix requires
  restructuring the rounded-corner fill.
- **#8** `.debug-panel` slides via `right` instead of `transform:
  translateX()` — flagged but recommended to skip; internal dev-only tool,
  not user-facing.
- **Missed opportunities** noted but not planned: the comment
  spoiler-reveal teleports instantly with no transition; the rating card's
  "Ваша оценка" button text swap after voting is instant with no fade.

Re-run `/improve-animations reconcile` after any of these plans lands to
mark it DONE and re-check the rest of the audit against the new code.
